# 테스트 담당과 환경 요청

기준일: 2026-11-06. 앱 0.3.x UI/UX 개선과 0.3.1 IME 오류 수정의 자동 검증·Android 확인 범위를 기록한다. 에이전트 실행, 관리자 보고와 미검증 범위를 구분한다. 기존 0.1.0 RTL·0.2.0 관리자 결과는 별도 이력으로 보존한다.

3번의 기존 완료 표시는 0.2.0에 대한 것이다. 0.3.0 결과와 검증 계획은 7번, 0.3.1 오류 수정과 에뮬레이터 확인은 8번에 기록한다.

## 1. 담당과 판정 기준

| 대상 | 담당 | 기준 |
| --- | --- | --- |
| 파싱·검색·저장 로직과 데스크톱 Chromium 점검 | 에이전트 | 합성 데이터로 자동화하고 검증 범위를 명시한다. |
| Android Chrome | 주 개발·검증 대상. 접근 가능한 실제 단말 또는 에뮬레이터에서 에이전트 검증, 필요 시 작업자 지원 | 실제 환경·버전을 기록한다. 모바일 화면 에뮬레이션만으로 Android 검증 완료를 선언하지 않는다. |
| 삼성 인터넷 | 작업자/관리자의 수동 테스트 | 문제점·개선사항을 제출하고 에이전트가 재현·수정·회귀 검증을 지원한다. |

에이전트의 삼성 인터넷 자동화 가능 여부는 구현 작업의 선행조건이 아니다. 수동 테스트를 수행하기 전에는 해당 브라우저를 미검증으로 표시한다. 프로젝트 관리자는 수동 테스트에서 발견한 문제의 우선순위와 출시 영향을 판단한다.

## 2. 현재 환경 요청 상태

2026-11-05 기존 설치 환경을 점검하고 가상 기기를 실행했다. 추가 설치 없이 에뮬레이터가 Android 홈 화면까지 부팅했고 ADB 연결을 확인했다. 이 문서의 기존 AVD 환경 점검과 아래 앱 검증 결과를 구분한다.

### 2.1 확인된 환경

| 항목 | 확인 결과 |
| --- | --- |
| Android Studio | 기존 설치 확인 |
| SDK | `D:\AndroidSDK` |
| Android Emulator | `36.1.9.0` |
| ADB Platform Tools | `36.0.0-13206524` |
| 가상 기기 | 기존 `Pixel_6_Pro`, x86_64, Google APIs 이미지 |
| Android | Android 16 / API 36 |
| VM 가속 | AEHD 2.2 사용 가능 |
| 부팅 | `sys.boot_completed=1`, 부팅 애니메이션 종료, 홈 화면 확인 |
| ADB 연결 | 점검 당시 `emulator-5554`, 상태 `device` |

| Chrome 웹페이지·CDP | 0.2.0 공개 페이지와 기본 편집 확인. CDP 연결은 미검증 |

기존 AVD를 그대로 실행했다. 가상 기기 초기화, 시스템 이미지 교체, 추가 SDK 설치, BIOS 또는 Windows 가상화 설정 변경은 수행하지 않았다. SDK/AVD 경로 환경 변수는 진단 프로세스에만 설정했으며 사용자 전역 환경 변수를 변경하지 않았다.

### 2.2 후속 자동화를 위한 선택 사항

- Chrome 첫 실행 설정과 공개 웹페이지 로딩은 후속 테스트에서 확인했다. CDP 자동화 연결은 별도 검증 대상이다.
- 설치된 Chrome 133을 최신 안정판 검증 환경으로 취급하지 않는다. 후속 에뮬레이터 검증 때 브라우저 업데이트 경로와 버전을 확인한다. 이번 관리자 실기기 환경은 6.3에 따로 기록한다.
- 현재 AVD는 Google APIs 이미지이며 `PlayStore.enabled=false`다. Play Store 사용이나 계정 로그인을 전제로 업데이트 절차를 확정하지 않는다. 업데이트를 위해 별도 이미지 또는 패키지가 필요하면 구체적인 작업과 용량을 확인해 요청사항으로 남긴다.
- 에뮬레이터의 기능·성능 결과와 실제 휴대폰 결과는 구분해 보고한다.

| 조건부 요청 | 필요한 시점 | 현재 상태 |
| --- | --- | --- |
| Android 에뮬레이터 접근 | 모바일 동작·PWA 검증 전 | 기존 AVD 부팅·ADB 연결 확인 |
| Android Studio/SDK/AVD 추가 설치 | 기존 환경을 사용할 수 없을 때 | 현재 필요 없음 |
| Chrome 첫 실행 설정·버전 정비 | 후속 에뮬레이터 검증 전 | 초기 설정 완료 · 버전 정비는 후속 자동화 시 검토 |
| ADB 포워딩·Chrome 원격 디버깅 | 후속 브라우저 자동화 연결 전 | 미검증 · 이번 기능 검증의 완료 조건은 아님 |
| 삼성 인터넷 수동 검증 | 검증 가능한 앱 버전 제공 후 | 2026-11-06 관리자 완료 보고, 6.3 참조 |

### 2.3 기존 환경 실행과 확인

로그인한 Windows 사용자 컨텍스트에서 기존 SDK를 사용한다. 가상 기기 이름과 실행 중인 기기의 serial은 매번 확인한다.

```powershell
& 'D:\AndroidSDK\emulator\emulator.exe' -list-avds
& 'D:\AndroidSDK\emulator\emulator.exe' -accel-check
& 'D:\AndroidSDK\emulator\emulator.exe' -avd Pixel_6_Pro
```

다른 터미널에서 확인한다.

```powershell
& 'D:\AndroidSDK\platform-tools\adb.exe' devices -l
& 'D:\AndroidSDK\platform-tools\adb.exe' -s emulator-5554 shell getprop sys.boot_completed
```

실제 단말 원격 디버깅도 후속 선택지다. Android Studio 없이 Chrome DevTools로 실기기를 연결할 수 있다. 단말 연결·디버깅 권한 허용 등이 필요하면 해당 시점에 요청사항으로 남긴다.

[UI_UX_IMPROVEMENTS.md](UI_UX_IMPROVEMENTS.md#7-수용-기준)의 U01–U14가 신규 완료 판정 기준이다. 이전 관리자 체크리스트 통과를 새 UI의 통과 결과로 사용하지 않는다.

### 7.1 자동 검증 완료

- Node.js 24.22.1, pnpm 11.25.0에서 테스트 26개 통과. TypeScript 검사·프로덕션 빌드 통과.
- 기존 CSV·검색·중복·백업·저장 트랜잭션·Service Worker VM 테스트를 유지했다.
- 느린 검색에서 진행 중 요청과 최신 대기 요청만 유지하고 오래된 응답이 다음 요청을 잘못 해제하지 않는 것을 확인했다.
- 실제 Worker 소스를 VM에서 실행해 느린 이전 사전 로드가 최신 인덱스를 덮지 않는 것을 확인했다.
- jsdom 30.1.3과 fake-indexeddb에서 앱 이벤트·화면 상태·저장을 함께 검증했다. 합성 조합 중 후보 표시·한 번 대체·취소 제스처·문맥 변경 보호, 패널 검색창과 본문 커서 분리·연속 삽입·조합 종료 대기, 미리보기 취소·개별 복사·복사 거절·빈 부정 교체가 통과했다.
- 저장 함수 실패와 IndexedDB 쓰기 실패·다른 탭 버전 충돌을 주입해 기존 초안과 DB 보존을 확인했다. 실제 브라우저 용량을 가득 채운 시험은 아니다.

DOM 테스트의 Worker·클립보드·dialog·viewport는 시험 대역이다. 합성 composition 이벤트와 좌표 계산 검증은 실제 Android IME, CSS 렌더링, 키보드 높이, 시스템 클립보드 또는 접근성 도구 검증을 대체하지 않는다. jsdom은 개발 의존성이며 앱 런타임에 포함하지 않는다.

### 7.2 화면 검증 중단과 현재 범위

기존 Pixel 6 Pro 에뮬레이터와 설치된 Chrome 실행을 시도했고 두 창이 반환된 것을 확인했다. 브라우저 자동화 연결은 Work 설정에서 비활성화되어 있었다. 네이티브 Chrome 창을 선택하는 단계에서 컴퓨터 조작 도구가 현재 URL을 충분한 신뢰도로 판별하지 못해 이번 턴의 조작을 중단했다. 이후 추가 UI 입력을 수행하지 않았으며, 신규 앱 페이지나 실제 키보드 동작을 확인하지 못했다.

새 SDK·시스템 이미지·브라우저를 설치하거나 AVD를 초기화하지 않았다. Android Studio 추가 설치 요청은 없다. 다음 실제 기기 점검은 관리자 수동 검증 또는 사용 가능한 브라우저/에뮬레이터 조작 환경에서 수행한다. 아래 항목은 모두 신규 실기기 확인 대기이며, 시행 시 기기·OS·브라우저·키보드·담당·대상 커밋을 기록한다.

### 7.3 신규 실제 기기 체크리스트 — 미실시

## 8. 앱 0.3.1 IME 대체 오류 수정

### 8.1 관리자 보고

0.3.0에서 다음 조건을 보고받았다. 이번 보고의 상세 기기·브라우저·키보드 조합은 별도 수집하지 않았으므로 이전 S25·태블릿 보고와 임의로 합치지 않는다.

| 조건 | 관리자 보고 |
| --- | --- |
| 태그 입력 직후 후보 대체 선택 | 입력 확정 안내 발생 |
| 태그 입력 후 후보 목록 스크롤, 대체 선택 | 입력 확정 안내 발생 |
| 공백 입력으로 확정한 뒤 후보 선택 | 정상 |
| 빈 곳을 눌러 키보드를 내린 뒤 후보 선택 | 정상 |

0.3.0 코드는 조합 중 후보 선택에서 blur를 호출하고 조합 종료·클릭 완료 조건을 기다렸다. 조합 종료 이벤트를 보내지 않는 DOM 재현 테스트에서 대체가 막히는 것을 수정 전에 확인했다. 실제 보고 기기의 이벤트 로그를 확보한 것은 아니므로 특정 브라우저·키보드의 이벤트 누락으로 원인을 단정하지 않는다.

### 8.2 수정과 자동 검증

- 종료 이벤트 대기와 900ms 재선택 안내를 제거하고, 클릭 시 원문·항목·대상·사전을 검증해 적용한다. 후보 포인터 누름은 편집 초점을 빼앗지 않으며 스크롤 취소는 적용하지 않는다.
- 조합 중에는 새 textarea 호스트로 원문·커서·스크롤·속성을 인계하고 사용자 클릭 안에서 초점을 유지한다. 퇴역한 호스트의 입력·조합 이벤트와 예약 마이크로태스크는 현재 초안을 변경하지 않는다. 조합 중이 아니면 기존 호스트를 유지한다.
- 같은 후보 내용은 DOM을 다시 만들지 않아 조합·선택 이벤트 중 버튼이 사라지는 것을 방지한다. 값 변화가 없는 후속 input은 삽입 취소 기록을 지우지 않는다.
- 자동 테스트 30개와 TypeScript 검사·프로덕션 빌드를 통과했다. 조합 종료 이벤트 없이 선택·초점 보존, 퇴역 호스트 이벤트 무시·단일 기록 집계, 스크롤 취소 후 가운데 항목 대체, 공백 확정 시 기존 호스트·공백 보존, 부정 원문·이웃 항목 보호를 확인했다. 패널 태그 삽입에도 종료 이벤트 없는 경우를 적용했다.

합성 이벤트와 DOM 초점 검증은 실제 키보드 표시·네이티브 조합 엔진의 완료 증거로 사용하지 않는다. 실제 Android 확인 결과는 별도로 기록한다.

### 8.3 Android 에뮬레이터 확인 (2026-11-06)

| 항목 | 환경·결과 |
| --- | --- |
| 대상 | 로컬 개발 서버의 앱 0.3.1, 공개 합성 예제 11행 |
| 기기 | Pixel 6 Pro AVD / Android 16 / API 36 |
| 브라우저 | Chrome 133.0.6943.137. 최신 안정판 검증으로 취급하지 않음 |
| 입력 | Gboard 15.1.08.726012951-preload-x86_64의 영문 화면 키보드. 필기 도구에서 임시로 띄운 플로팅 QWERTY 사용 |
| 직접 선택 | 화면 키로 `blue e` 입력 후 추가 공백·키보드 내림 없이 후보 선택 → `blue eyes`. 확정 안내 없음, 키보드 표시 유지 |
| 후속 입력 | 대체 후 `x` 입력 → `blue eyesx`. 기존 입력이 다시 나타나거나 태그가 덮이지 않음 |
| 스크롤 후 선택 | `l` 입력 → 후보 목록을 위로 드래그해 아래 후보 탐색 → `sample character` 선택. 대체 적용·키보드 표시 유지, 확정 안내 없음 |

네이티브 화면과 실제 Gboard 키 탭으로 확인했다. 호스트 키 입력·붙여넣기 전달이 원활하지 않아 주소와 테스트 문자열은 화면 키로 입력했다. 기기 설정·SDK·언어팩을 추가하거나 개인 CSV를 전송하지 않았다.

이 확인은 영문 입력·플로팅 키보드에 한정한다. 해당 입력의 정확한 composition 이벤트 순서를 수집한 것은 아니며, 한글 조합·삼성 키보드·삼성 브라우저·일반 도킹 키보드 전체를 검증한 것으로 확대하지 않는다. 조합 종료 이벤트가 없는 분기의 보호 동작은 DOM 테스트로 확인한 범위다.

- [ ] 관리자 실기기에서 한글 입력 직후 후보 선택과 후보 스크롤 후 선택을 재확인. 공백 입력·키보드 내림을 선행하지 않아도 대체되고 키보드가 유지되는지 확인.
- [ ] 삼성 키보드·삼성 브라우저에서 대체 후 이어 입력, 원문 중복·덮어쓰기·커서 이동 여부 확인. 시행 시 실제 환경과 대상 버전을 기록.
