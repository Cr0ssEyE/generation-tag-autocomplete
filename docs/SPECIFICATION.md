# Generation Tag AutoComplete 작업 명세서

- 문서 버전: 0.2
- 기준일: 2026-11-05
- 상태: 초기 구현을 위한 명세. 앱 구현 전.
- 앱 이름: Generation Tag AutoComplete
- 한글 설명: 이미지 생성 프롬프트 작성 보조 툴
- 저장소: Public, 권장 이름 `generation-tag-autocomplete`
- 배포: GitHub Pages 기반 정적 웹/PWA
- 코드 라이선스: MIT

## 1. 목적과 사용 흐름

Android 휴대폰·태블릿에서 개인 CSV를 사용해 이미지 생성 프롬프트를 작성한다. CSV, 검색, 프롬프트, 기록, 라이브러리는 단말에서 처리한다.

사용자는 PWA에서 작성·저장·복사를 수행한 뒤 기존 원격 프로그램을 통해 집 PC로 전달한다. 원격 프로그램의 장문 전달은 사용자가 이미 확인했으므로 본 프로젝트의 검증·개발 범위에 포함하지 않는다.

기본 흐름은 `CSV 가져오기 → 검색 또는 기록에서 태그 선택 → 긍정/부정 원문 편집 → 저장 또는 복사`이다. CSV가 없을 때도 편집·저장·복사는 사용할 수 있다.

## 2. 합의한 범위

### 2.1 첫 버전에 포함

1. UTF-8 CSV 가져오기, 사전 보관·선택·교체·삭제.
2. 영문 태그와 한글 설명의 부분 문자열 검색 및 공백 차이 보정.
3. 유형코드 필터와 카운트를 보조 기준으로 한 정렬.
4. 별도 검색창과 긍정·부정 원문 편집기.
5. `검색 / 기록` 전환 탭에서 사용 태그 확인과 재사용.
6. 사용 중 표시와 같은 편집기 내의 중복 태그 삽입 방지.
7. 초안 자동 저장, 이름을 붙인 프롬프트, 태그 즐겨찾기와 태그 묶음.
8. 복사, 수동 선택 대안, JSON 백업과 전체 복원.
9. 홈 화면 설치, 오프라인 실행, 앱 전환·재실행 후 복원.
10. Android Chrome 중심의 개발·검증과 작업자/관리자의 삼성 인터넷 수동 테스트 피드백 반영.

### 2.2 첫 버전에서 제외

태그 칩, AND/OR·정규식·의미·초성 검색, 번역·동의어 자동 생성, 언더스코어 변환, 가중치 해석·편집, CSV 내용 편집·사전 병합, 직접 PC 통신, ComfyUI API 조작, 이미지 생성·결과 수신, 클라우드 저장·동기화·계정, APK, Apple 환경 지원.

OS 백업과 시스템/원격 도구의 클립보드 동기화는 앱의 관리 범위 밖이다.

## 3. 지원 환경과 화면

Android Chrome의 구현 검증 시점 최신 안정 버전을 주 개발·검증 대상으로 삼는다. 삼성 인터넷도 호환 대상에 두되 작업자/관리자가 직접 테스트하고 문제점과 개선사항을 제안한다. 에이전트는 삼성 인터넷 자동화 환경 확보를 필수 선행조건으로 삼지 않는다.

실제 시험에 사용한 Android 버전·기기·브라우저 버전과 테스트 담당을 기록한다. Android Chrome의 실제 단말 또는 에뮬레이터에 접근할 수 없으면 미검증으로 표시하고 필요한 환경을 요청한다. 데스크톱 모바일 화면 에뮬레이션 결과로 Android 테스트를 대체했다고 보고하지 않는다. 환경 요청과 수동 테스트 절차는 [테스트 담당과 환경 요청](TESTING.md)을 따른다.

주요 화면은 편집, 사전 관리, 라이브러리, 설정/백업이다. 휴대폰은 검색/기록과 현재 편집기를 순차적으로 보기 좋게 배치하고, 태블릿은 공간에 따라 나란히 배치한다. 가상 키보드가 열린 상태에서도 후보 선택과 주요 편집 조작이 가능해야 한다.

편집 화면에는 다음 요소를 둔다.

- 현재 사전과 현재 삽입 대상인 `긍정 / 부정` 표시.
- `검색 / 기록` 전환 토글 탭.
- 검색 탭의 검색창·유형 필터·후보 목록.
- 기록 탭의 최근 사용 태그 목록과 재사용 버튼.
- 긍정·부정 원문 편집기 및 각각의 복사 버튼.
- 초안 저장 상태, 이름을 붙여 저장, 라이브러리 접근.

설명과 태그는 일반 텍스트로 렌더링한다. `<인원>` 등의 문자열을 HTML로 해석하지 않는다. 긴 태그와 설명이 화면 밖으로 넘치지 않도록 줄바꿈하고, 후보에서 설명을 펼쳐 볼 수 있게 한다.

## 4. CSV 가져오기와 사전 수명

상세 파싱 규칙은 [CSV 규격](CSV_FORMAT.md)을 따른다. 파일 선택으로 가져온 내용을 단말의 앱 저장소에 사본으로 보관한다. 원본 파일을 수정하거나 변경을 감시하지 않는다.

여러 사전을 보관할 수 있으며 검색에는 한 사전을 활성화한다. 사전 교체 시 같은 논리 사전 ID를 유지하고, 새로운 내용과 인덱스가 준비된 후 교체를 확정한다. 새 사전으로 추가하는 동작은 별도로 제공한다.

파싱 중 진행·취소 상태를 제공한다. 오류 행 수와 오류 이유를 표시하되 원본 설명 전체를 로그에 남기지 않는다. 치명적 형식 오류, 저장 용량 부족, 취소는 기존 사전과 활성 상태를 변경하지 않는다. 유효 행이 0개인 파일은 가져오지 않는다.

사전 삭제·교체는 초안, 저장 프롬프트, 기록, 즐겨찾기, 태그 묶음을 삭제하지 않는다. 사전이 없어진 태그도 보관된 태그 문자열로 재사용할 수 있다. 해당 사전의 설명은 사전이 없으면 표시하지 않아도 된다.

## 5. 검색 규칙

### 5.1 일치 판정

검색 대상은 원본 태그와 설명이다. 유형코드는 필터, 카운트는 정렬에만 사용한다.

검색 전 Unicode NFC 정규화, 영문 대소문자 통일, 양끝 공백 제거를 수행한다. 원문 부분 일치와 모든 공백을 제거한 보조 문자열의 부분 일치를 사용한다. 정규화는 검색용 데이터에만 적용한다. 언더스코어·숫자·단어 의미는 자동 변환하지 않는다.

검색어 전체를 하나의 문자열로 취급한다. 예제 사전에서 `여자 1명`, `여자1명`, `여성한명`은 `1girl`에 일치하고, `여성 1명`과 `여자 인원수`는 일치하지 않는다. 빈 검색어는 전체 사전을 나열하지 않고 최근 사용·즐겨찾기 접근을 제공한다.

한글 1자도 검색할 수 있다. IME 조합을 방해하지 않으며 조합 중 임시 입력으로 후보를 확정하지 않는다. 첫 구현의 검색 대기 기본값은 120ms, 표시 후보 상한은 20개로 둔다.

### 5.2 정렬

1. 검색 정규화 후 태그 완전 일치.
2. 태그 앞부분 일치.
3. 태그 내부 부분 일치.
4. 설명 부분 일치.

같은 그룹에서는 태그카운트 내림차순, 이후 원본 태그의 고정된 문자열 순서로 정렬한다. 카운트를 프롬프트 품질 점수로 표시하지 않는다. 유형 필터와 사용 중 상태는 후보에 함께 적용한다.

검색 준비와 검색은 Web Worker에서 수행한다. 요청 순번으로 오래된 응답을 버려 빠른 입력 중 이전 결과가 최신 결과를 덮지 않게 한다. IndexedDB 저장 자체를 전문 검색 인덱스로 간주하지 않는다.

## 6. 원문 편집과 태그 삽입

긍정·부정 프롬프트는 독립된 문자열이며 원문이 기준 데이터다. 직접 입력·붙여넣기·선택·삭제·실행 취소를 지원한다. 수동으로 쓴 괄호나 가중치 문자열은 그대로 보관하고 별도로 해석하지 않는다.

검색/기록으로 초점이 이동해도 마지막으로 선택한 편집기와 선택 범위를 보관한다. 후보 선택은 그 범위에 원본 태그를 삽입하거나 선택된 문자열을 대체한다. 사용자 동작 없이 다른 단어 전체나 주변 문장을 대체하지 않는다. 최초 삽입 대상은 긍정, 보관된 위치가 유효하지 않으면 해당 편집기 끝이다.

태그 사이의 기본 구분자는 `, `이다. 삽입 경계에서 쉼표가 연속으로 생기지 않도록 처리한다. 기존 원문 전체의 공백·구두점·순서를 일괄 수정하지 않는다. 태그 자체에 포함된 공백과 `@` 등은 보존한다.

사용 중 판정은 현재 삽입 대상 편집기에서 쉼표·줄바꿈으로 나뉜 항목의 양끝 공백을 제거한 뒤 NFC로 비교한다. 태그 내부 공백이나 영문 대소문자를 임의로 바꾸지 않는다. 문장의 일부에 태그 문자열이 포함된 것만으로 사용 중으로 판단하지 않는다. 수동 가중치·그룹 구문 내부의 태그를 추출하는 작업은 범위 밖이다.

이미 사용 중인 후보는 목록에 남겨 `사용 중`으로 표시하고 추가 동작을 비활성화한다. 긍정과 부정 사이의 중복은 각각 독립적으로 판단한다. 태그 묶음 삽입도 현재 대상에서 이미 사용한 태그를 제외하고 원래 묶음 순서로 추가한다.

## 7. 기록 탭

이번 명세에서 사용자의 '토글 형식 탭'은 `검색 / 기록` 화면을 전환하는 토글로 해석한다. 기록 행은 태그 문자열과 재사용 동작을 제공하며 태그 칩으로 표시하지 않는다.

- 자동완성, 기록, 즐겨찾기, 태그 묶음에서 실제 삽입에 성공한 태그만 사용 기록을 갱신한다.
- 자유서술을 입력하거나 복사했을 때 본문에서 태그를 자동 추출하지 않는다.
- 동일한 태그 문자열은 기록 하나로 합치고 최근 사용 시각·사용 횟수를 갱신한다.
- 첫 버전은 최근 사용 순서, 최대 1,000개 고유 태그를 기본으로 한다. 초과하면 가장 오래된 기록부터 제거한다.
- 기록은 긍정·부정 공용이다. 재사용은 현재 선택한 편집기로 수행하며 사용 중 표시도 그 편집기를 기준으로 한다.
- 개별 기록 삭제와 전체 기록 삭제를 제공한다. 기록 삭제는 편집기와 저장 프롬프트를 변경하지 않는다.
- 기록은 사전 삭제 후에도 태그 문자열로 재사용 가능하다. 설명은 연결 가능한 로컬 사전이 있을 때만 표시한다.

## 8. 저장·라이브러리·복사

현재 긍정·부정 초안과 삽입 대상, 선택 사전, 필터, 탭 상태를 저장한다. 초안은 입력 중 짧은 지연을 두고 지속 저장하며 저장 성공 여부를 표시한다. blur, 탭 전환, 페이지 숨김에서 가능한 저장을 수행하되 종료 이벤트 한 번에만 의존하지 않는다. 저장 실패를 성공으로 표시하지 않는다.

라이브러리 항목은 이름, 긍정·부정 원문, 생성·수정 시각으로 구성한다. 불러오기는 현재 초안을 교체하므로 기존 초안의 저장 상태를 확인하고 교체 안내를 제공한다. 즐겨찾기는 태그 문자열 기준으로 보관하고 태그 묶음은 이름과 순서 있는 태그 배열로 보관한다. 사전은 이들의 소유자가 아니다.

복사는 사용자가 누른 긍정/부정 버튼에 해당하는 최종 원문만 시스템 클립보드에 기록한다. 설명·유형코드·카운트를 포함하지 않는다. 성공 응답 후 복사 성공을 표시하고, 거부 또는 실패 시 원문 선택으로 수동 복사할 수 있게 한다.

## 9. 단말 저장과 데이터 구조

IndexedDB를 사용한다. 초기 데이터 단위는 다음과 같다. 구체적 필드 및 DB 마이그레이션은 구현 시 버전으로 관리한다.

| 단위 | 내용 |
| --- | --- |
| dictionaries | 논리 ID, 표시 이름, 원본 파일명, 행 수, 유형 정보, 변경 시각, 로컬 파일 지문, 데이터 버전 |
| dictionaryRows | 사전 ID, 태그, 유형코드, 카운트, 원본 설명 |
| drafts | 현재 긍정·부정 원문과 편집 상태 |
| prompts | 이름을 붙인 긍정·부정 프롬프트 |
| favorites | 태그 문자열과 추가 시각, 선택적인 사전 참조 |
| tagGroups | 이름과 순서 있는 태그 배열 |
| history | 태그 문자열, 최근 사용 시각, 사용 횟수, 선택적인 사전 참조 |
| settings | UI 설정, 선택 사전 및 탭 상태 |

활성 사전만 검색 작업에 올리는 방향을 기본으로 한다. 원본·정규화 설명·메시지 전달 사본이 불필요하게 중복되지 않게 한다. 실제 CSV는 저장소 또는 배포물에 포함하지 않는다.

브라우저 지속 저장 요청과 저장 공간 상태 확인을 제공하되 허용을 보장하지 않는다. 앱 데이터 삭제는 해당 앱 저장소에만 적용하며 다른 프로젝트의 같은 출처 데이터를 지우지 않는다. 전용 DB 이름과 Service Worker 범위를 사용한다.

## 10. JSON 백업과 전체 복원

백업은 UTF-8 JSON이다. 필수 상위 필드는 `schemaVersion`, `appId`, `exportedAt`, `data`이며 `appId`는 `generation-tag-autocomplete`이다.

`data`에 초안, 저장 프롬프트, 즐겨찾기, 태그 묶음, 사용 기록, 설정과 사전 식별 정보를 포함한다. CSV 본문, 전체 사전 행, 검색 인덱스, 단말 절대 경로는 포함하지 않는다. 사전은 원본 CSV를 다시 가져와 연결한다. 파일명은 `generation-tag-autocomplete-backup-YYYYMMDD-HHmmss.json`으로 한다.

복원은 사용자 데이터 전체 교체 방식이다. 현재 데이터 내보내기를 제공하고 교체 범위를 안내한 뒤 실행한다. 먼저 JSON 문법, 앱 ID, 스키마 버전, 필드 타입과 참조를 검증한다. 지원하지 않는 미래 버전은 기존 데이터 변경 없이 거절한다.

백업에 없는 CSV 본문은 현재 단말의 사전 보관소를 삭제하지 않는다. 복원 후 이름만으로 사전을 자동 연결하지 않고 확인 가능한 지문/식별 정보로 연결한다. 연결할 수 없으면 사전 선택을 해제하고 다시 가져오도록 안내한다. 프롬프트·기록·즐겨찾기의 원문은 계속 사용할 수 있다.

검증과 새 데이터 쓰기를 하나의 트랜잭션으로 처리하고 실패 시 전체 롤백한다. 저장 프롬프트·즐겨찾기 등의 병합 복원은 첫 버전에 포함하지 않는다.

## 11. PWA와 네트워크 경계

호스팅에는 앱 HTML/CSS/JS, 아이콘, manifest, 라이선스 고지, 합성 예제만 배포한다. 개인 데이터용 서버와 API를 만들지 않는다. 라이브러리·폰트도 배포물에 포함해 런타임 외부 의존성을 줄인다.

최초 앱 리소스를 내려받고 저장한 뒤 오프라인에서 실행·CSV 가져오기·검색·편집·저장·복사가 가능해야 한다. Service Worker는 앱 리소스를 캐시하고, 개인 CSV와 프롬프트는 IndexedDB에서 관리한다. 사용자 내용은 URL, 요청 본문, 원격 로그, 분석·오류 수집 서비스에 넣지 않는다.

앱 업데이트가 있어도 편집 중 강제 새로고침하지 않는다. 저장 후 사용자가 적용할 수 있게 안내한다. 데이터 마이그레이션 실패 시 기존 데이터를 보존하고 복구·내보내기 경로를 제공한다.

GitHub Pages의 프로젝트 하위 경로에 맞는 asset base, manifest scope/start URL, Service Worker scope를 설정한다. 다른 도메인·브라우저로 데이터가 자동 이전되는 동작은 제공하지 않고 JSON으로 이전한다.

## 12. 구현을 위한 기술 방향

서버 없는 정적 클라이언트, 타입이 있는 코드, CSV 파서, Web Worker, IndexedDB, PWA 리소스 캐시로 구성한다. 화면, 순수 검색/파싱 로직, 데이터 저장 어댑터를 분리한다.

프레임워크·빌드 도구·패키지 버전은 구현 첫 단계에서 선택하고 잠금 파일로 고정한다. 이 문서는 특정 프레임워크를 사용자의 확정 결정으로 취급하지 않는다. 후속 APK 전환을 위해 첫 버전에 네이티브 의존성을 미리 넣지 않는다.

| A06 | 사용 기록이 최근순으로 표시되고 재사용·개별 삭제·전체 삭제가 정의한 데이터 수명을 따른다. |
| A07 | 앱 전환·재실행 후 마지막으로 저장된 양쪽 초안과 편집 상태가 복원된다. |
| A08 | 사전 교체·삭제 후에도 저장 프롬프트·즐겨찾기·태그 묶음·기록이 유지된다. |
| A09 | 백업 내보내기·전체 복원으로 개인 편집 데이터를 재현하고, 잘못된 JSON과 미지원 버전은 기존 데이터를 보존한다. |
| A10 | 리소스 준비 후 비행기 모드에서 가져오기·검색·편집·저장·재실행·복사를 수행한다. |
| A11 | 네트워크 검사에서 CSV·검색어·프롬프트가 요청·URL·원격 로그로 전송되지 않는다. |
| A12 | Android Chrome을 주 기준으로 파일 선택, IME, 키보드 레이아웃, 복사, PWA 재실행을 검증한다. 삼성 인터넷은 작업자/관리자가 수동 테스트하고 결과와 피드백을 별도로 기록한다. |
| A13 | 공개 Git 파일과 배포 산출물에 실제 CSV·개인 백업·단말 데이터가 포함되지 않는다. |

실제 로컬 사전의 기준 규모는 약 134,020행·24.66MiB다. 파일명과 내용을 공개 문서·테스트에 복제하지 않는다. 초기 가져오기 시간, 준비 후 검색 지연의 p50/p95, 메모리 영향과 UI 정지를 실제 단말에서 측정한다. 준비 후 검색 p95 150ms 이내(입력 대기 제외)를 초기 목표로 두되, 목표 달성 여부와 기기 조건을 기록하고 최적화 범위를 판단한다.

## 14. 명세 작성 시 구체화한 기본값

아래는 사용자 합의를 구현 가능하게 구체화한 기본값이다. 구현 중 조정 시 이 표와 관련 수용 기준을 갱신한다.

| 항목 | 기본값 |
| --- | --- |
| 기록 UI | 검색/기록 전환 탭, 행 목록과 재사용 버튼 |
| 기록 범위 | 양쪽 편집기 공용, 실제 삽입 성공만 집계 |
| 기록 보관 | 태그별 통합, 최근순, 최대 1,000개 |
| 검색 | 단일 문자열 부분 일치 + 공백 보정, 대기 120ms, 후보 20개 |
| 사전 | 여러 개 보관, 한 개 활성화, 병합 없음 |
| JSON | 스키마 버전 1, 기록·초안 포함, 전체 사전 본문 제외 |
| 복원 | 사용자 데이터 전체 교체, 로컬 CSV 보관소는 보존 |
| 표시 이름 | Generation Tag AutoComplete / 이미지 생성 프롬프트 작성 보조 툴 |

GitHub 소유 계정, 최종 원격 URL, 실제 단말 모델, 도구 버전은 해당 단계에서 확인할 운영 정보다. 이 정보가 없어도 초기 구현 준비를 진행할 수 있다.
