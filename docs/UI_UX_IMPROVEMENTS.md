## 1. 목적과 범위

키보드를 사용하는 Android 휴대폰·태블릿에서 입력 도중 태그 후보를 확인하고, 태그 찾기와 저장 프롬프트 불러오기를 편하게 사용할 수 있게 한다.

| 구분 | 이번 작업 |
| --- | --- |
| 자동완성 | 120ms 입력 대기 후 검색. 한글 IME 조합 중에도 현재 입력으로 후보 표시 |
| 프롬프트 불러오기 | 긍정·부정 전체 원문을 함께 보여주는 미리보기, 개별 복사, 명시적인 양쪽 초안 교체 |
| 빈 프롬프트 | 저장된 부정 원문이 비어 있으면 현재 부정 초안도 빈 문자열로 교체. 긍정도 같은 원칙 적용 |
| 태그 찾기 | 편집 화면 전용 측면 버튼으로 여닫는 오버레이 패널. 북마크·유형 탐색·기록 유지 |
| 지속 저장 | 기존 요청 버튼과 실제 브라우저 상태 표시 유지. 토글 등 추가 변경 없음 |

입력마다 대기 없이 검색하는 방식은 모바일 정량 성능을 확인한 후 별도 판단한다. 이번 기본값은 120ms이며 검색 대기 시간 설정 UI는 추가하지 않는다. 태그 자동 삽입·자동 확정, 드래그 열기·버튼 위치 드래그·패널 크기 조절, 불러오기 전 초안의 별도 되돌리기 이력은 이번 범위에 포함하지 않는다.

## 2. 입력 중 자동완성

### 2.1 검색 시점과 대상

1. 입력·삭제·붙여넣기·한글 조합 갱신 후 120ms 동안 추가 변경이 없으면 검색한다. 글자 확정, 공백, 쉼표 또는 입력창 이탈을 기다리지 않는다.
2. 검색어는 현재 커서가 있는 쉼표·줄바꿈 항목 전체다. IME 조합 중에도 입력창에 현재 표시된 원문과 선택 범위를 기준으로 한다. 조합 이벤트의 일부 문자열만으로 본문을 재구성하지 않는다.
3. 커서·선택 범위·긍정/부정 대상·활성 사전이 바뀌면 최신 문맥으로 갱신한다. 조합 종료 때도 최종 원문과 커서를 다시 읽는다. 같은 내용의 중복 이벤트 때문에 동일 검색을 불필요하게 반복하지 않는다.
4. 빈 항목, 구분자를 가로지른 선택, 수동 괄호·가중치 구문 보호는 기존 규칙을 따른다. 한글 자모 입력도 일반 부분 일치로 처리하며 초성 검색을 새로 추가하지 않는다.
5. 후보를 보여주는 것만으로 조합을 확정하거나 본문·기록을 변경하지 않는다. 자동완성 후보는 기존과 같이 최대 20개다.

### 2.2 후보 선택과 IME 보호

- 조합 중이라는 이유로 후보 검색·표시·선택을 일괄 차단하지 않는다. 조합 중 후보 한 번 선택으로 태그를 적용할 수 있는 경로를 제공한다.
- 후보 버튼의 포인터 누름으로 편집기 초점을 빼앗지 않고, 실제 클릭 시 현재 원문·항목·대상·사전을 검증해 한 번 대체한다. 스크롤·포인터 취소는 대체를 실행하지 않는다. 같은 후보 내용은 매 이벤트마다 DOM을 다시 만들지 않아 클릭 도중 버튼이 사라지는 것을 방지한다.
- 조합 중 대체는 현재 값·선택 범위·스크롤·속성을 보존한 새 입력 호스트로 넘기고 사용자 클릭 안에서 초점을 유지한다. 이전 호스트를 퇴역 처리해 이후 입력·조합 이벤트와 이미 예약된 마이크로태스크가 현재 초안을 바꾸지 못하게 한다. 조합 중이 아니면 기존 호스트를 유지한다.
- 조합 종료 이벤트 수신이나 900ms 대기를 대체 조건으로 삼지 않으며, 편집기를 명시적으로 blur 처리하거나 일반 대체에서 입력 확정·재선택을 요구하지 않는다. 문맥이 달라진 경우 원문을 유지하고 최신 후보를 다시 제시한다. 가상 조합 이벤트로 실제 IME 확정을 흉내 내지 않는다.
- 후보 선택과 뒤따르는 `compositionend`·`input` 이벤트 때문에 태그가 중복되거나 원래 한글이 다시 들어가지 않아야 한다. 정상 삽입의 기록·삽입 취소는 한 번만 갱신한다.
- 기존의 현재 항목 대체, 구분자·주변 원문 보존, 일치/사용 중 표시, 긍정·부정별 커서와 중복 판정을 유지한다. 일반 후보 선택에서는 편집 초점과 키보드를 불필요하게 잃지 않게 한다.

### 2.3 검색 부하와 표시 안정성

검색은 Worker에서 수행한다. 자동완성 요청은 실행 중인 검색 외에 최신 대기 요청 하나만 유지해 오래된 검색이 계속 쌓이지 않게 한다. 응답에는 요청 순번과 사전·검색 문맥을 확인하고, 오래된 결과를 폐기한다. 보조 패널의 유형 탐색과 자동완성은 서로의 결과나 필터를 덮어쓰지 않는다.

입력할 때마다 후보 영역 전체가 사라졌다 나타나지 않도록 높이와 상태 표시를 안정적으로 유지한다. 이전 결과를 잠시 보여주는 경우에도 현재 검색 문맥과 다른 후보를 잘못 선택할 수 없게 한다. 사전 없음·로딩·결과 없음·검색 중 상태는 구분한다.

## 3. 저장 프롬프트 미리보기와 불러오기

### 3.1 화면

라이브러리의 불러오기 버튼은 즉시 교체하지 않고 별도 팝업을 연다. 팝업에는 저장한 이름, 긍정 원문, 부정 원문을 함께 표시한다. 내용을 편집하는 팝업은 아니다.

긴 원문도 생략 없이 확인할 수 있게 줄바꿈·스크롤을 제공한다. 긍정·부정 구역과 각 복사 버튼을 구분하고, 제목·닫기·취소·교체 버튼은 접근 가능한 위치에 유지한다. 높이는 실제 보이는 화면에 맞추고 가로 넘침을 방지한다.

버튼은 `긍정 복사`, `부정 복사`, `취소`, `양쪽 초안 교체`로 구분한다. 빈 구역은 `내용 없음 — 불러오면 현재 초안이 비워집니다`라고 표시하고 해당 복사 버튼은 비활성화한다. 초기 초점은 취소 등 비파괴 동작에 둔다.

### 3.2 복사와 취소

- 각 복사 버튼은 해당 저장 원문 전체만 복사한다. 초안·사용 기록·삽입 대상·커서·삽입 취소 기록을 변경하거나 불러오기를 실행하지 않는다.
- Clipboard API 성공 응답을 받은 뒤 성공으로 표시한다. 실패 시 팝업에서 원문을 선택해 수동 복사할 수 있게 한다.
- 취소, 닫기, Esc 또는 팝업 바깥 선택은 초안 교체 없이 닫는다. 키보드 표시 중의 시스템 뒤로가기 처리는 브라우저 동작을 존중한다.
- 미리보기 열기·복사·취소를 저장 프롬프트의 수정으로 취급하지 않는다. 원래 라이브러리 위치로 돌아가며 기존 초안과 편집 상태를 유지한다. 이미 대기 중이던 초안 자동 저장은 계속 허용한다.

### 3.3 명시적인 전체 교체

`양쪽 초안 교체`를 선택해야만 긍정·부정 원문을 함께 교체한다. 저장된 빈 문자열도 그대로 적용한다. 현재 초안에 내용을 이어 붙이거나, 빈 부정 원문을 이유로 기존 부정 초안을 남기지 않는다.

기존 저장 큐와 다른 탭 충돌 검사를 유지한다. 현재 초안의 저장 실패·충돌이 있으면 교체를 진행하지 않는다. 새 초안의 양쪽 원문을 한 동작으로 저장하고, 저장 실패 시 기존 초안을 보존하며 성공으로 표시하지 않는다. 중복 확인 클릭으로 교체를 반복하지 않는다.

성공 시 팝업을 닫고 편집 화면으로 전환한다. 기존 긍정/부정 선택을 유지하고 각 커서는 새 원문 끝으로 둔다. 양쪽 기존 삽입 취소 기록은 비운다. 라이브러리 원본·북마크·태그 묶음·사용 기록은 바꾸지 않는다. 키보드나 태그 찾기 패널을 자동으로 열지 않는다.

## 4. 측면 버튼과 태그 찾기 패널

### 4.1 버튼

- 편집 화면에서만 오른쪽 측면에 `태그 찾기` 버튼을 상시 표시한다. 다른 메뉴에서는 버튼과 패널을 숨긴다.
- 본문 스크롤과 관계없이 접근할 수 있게 고정한다. 기준 위치는 상단 고정 메뉴 아래부터 키보드 위까지 실제 보이는 영역의 세로 중간이다. 물리 화면 비율이나 고정 픽셀 높이만으로 배치하지 않는다.
- 주소창·키보드·화면 회전·안전 영역이 바뀌면 위치를 보정한다. 버튼의 터치 영역은 최소 44×44 CSS px로 하고 화면 바깥으로 밀리지 않게 한다. 편집·복사·후보 선택을 가리는지 실제 화면에서 확인한다.
- 누르면 패널을 열고, 다시 누르면 닫는다. 패널에도 별도 닫기 버튼을 둔다. 가장자리 스와이프나 드래그는 필수 조작으로 사용하지 않는다.
- 보조기술에 버튼 이름, 제어하는 패널, 열림 상태를 제공한다.

### 4.2 패널 배치

오른쪽에서 나타나 편집 화면 위를 덮는 패널을 사용한다. 기존 본문 안의 접이식 태그 찾기는 이 패널로 대체하며 같은 기능을 중복 표시하지 않는다. 열기·닫기 애니메이션은 필수 기능으로 삼지 않고 모션 감소 설정을 존중한다.

휴대폰에서는 측면 버튼 조작 여백 56 CSS px를 제외한 가용 너비를 사용하고 넓은 화면에서는 최대 480 CSS px를 기본값으로 한다. 상단 주요 메뉴와 키보드 영역은 덮지 않으며, 실제 보이는 높이에 맞춘다. 키보드가 열린 경우에도 제목·닫기·탭과 목록에 접근할 수 있게 한다. 넓은 화면에서도 최초에는 닫힌 상태이며 자동 고정 분할 배치는 이번 범위에서 제외한다.

패널을 위해 기존 편집기·자동완성 영역의 높이나 폭을 줄여 재배치하지 않는다. 패널 사용 중에는 뒤의 편집 화면이 일시적으로 가려질 수 있다. 목록은 패널 안에서 스크롤하고 제목·닫기·삽입 대상·탭·해당 탭의 조작부는 접근 가능하게 유지한다. 패널 스크롤이 뒤의 본문까지 이어지지 않게 한다.

가로 화면이나 분할 화면에서 가용 높이가 너무 작으면 제목·닫기만 고정하고 나머지 조작부와 목록을 패널 본문에서 함께 스크롤한다. 모든 조작부를 고정하느라 목록이 사라지는 배치를 피한다. 키보드를 강제로 숨겨 공간을 확보하는 방식에 의존하지 않는다.

### 4.3 초점·키보드·삽입 위치

열기만을 위해 편집기에 명시적으로 `blur()`를 호출하거나 패널 검색창에 자동 초점을 주지 않는다. 키보드가 열린 상태에서도 패널을 사용할 수 있도록 설계한다. 브라우저의 실제 키보드·초점 동작은 기기 검증에서 별도로 기록한다. 키보드 접근으로 패널을 열 때는 패널 조작부에 접근하고 닫은 뒤 열기 버튼으로 돌아올 수 있게 한다.

패널을 열기 전 마지막 긍정/부정 대상과 선택 범위를 보관한다. 패널 헤더에는 `삽입 대상: 긍정` 또는 `삽입 대상: 부정`을 표시한다. 패널 검색창의 커서를 프롬프트 커서로 사용하지 않는다. 패널 안의 별도 삽입 대상 전환 UI는 추가하지 않는다.

태그 선택은 보관한 편집 위치에 기존 삽입 규칙으로 적용한다. 조합 중 삽입에도 입력 호스트 인계를 적용하며, 본문이 실제 초점을 갖고 있을 때만 새 본문 호스트로 초점을 잇는다. 패널 검색창에 초점이 있으면 유지한다. 삽입 후에도 패널을 유지하고 최신 삽입 위치로 갱신해 여러 태그를 연속으로 추가할 수 있게 한다. 사용 중 표시와 기록은 삽입 대상 편집기 기준으로 갱신한다.

닫기 버튼, 측면 버튼, 패널 밖 편집 영역 선택 또는 Esc로 닫는다. 바깥 선택을 태그 삽입으로 처리하지 않는다. 다른 주요 메뉴를 선택하면 패널을 닫고 정상 이동한다. 시스템의 뒤로가기 제스처를 패널용 드래그로 대체하지 않는다.

### 4.4 기능과 상태 보존

기존 북마크·유형 탐색·기록을 유지한다. 유형만 선택한 상위 20개 탐색, 검색어로 좁히기, 기록 재사용·삭제, 북마크 조작, 사전이 없는 태그의 재사용 규칙도 유지한다. 유형 필터는 원문 자동완성에 영향을 주지 않는다.

선택 탭·필터 등 기존 저장 설정은 유지한다. 탭별 목록 스크롤 위치와 열림 상태는 현재 화면 세션에서 보관해 닫았다 다시 열 때 유지한다. 다른 주요 메뉴로 이동하거나 새로 실행하면 패널은 닫힌 상태다. 패널을 닫아도 원문·커서·자동완성 표시 위치가 초기화되지 않는다.

## 5. 데이터와 기존 기능의 경계

CSV 형식·검색 정규화·정렬·태그 원문·중복 판정·사전과 개인 데이터의 수명은 변경하지 않는다. 초안 자동 저장, JSON 스키마 1과 전체 복원, 오프라인 PWA, 브라우저 지속 저장 요청도 기존 계약을 유지한다.

미리보기, 열린 패널, 검색 요청, 탭별 임시 스크롤 위치는 실행 중 UI 상태다. 이 작업만을 위해 DB·JSON 스키마 변경을 요구하지 않는다. 실제 구현에서 영구 데이터 변경이 필요하면 호환성과 마이그레이션을 별도로 검토한다.

개인 CSV·실제 프롬프트·백업 원문은 공개 문서·테스트·스크린샷·CI·공유 기기에 포함하지 않는다. 공개 검증에는 기존 합성 예제 또는 새로 검토한 합성 데이터를 사용한다. 개인 사전은 관리자의 단말 또는 승인된 로컬 측정 환경에서만 사용한다.

## 6. 구현 순서

1. 자동완성의 IME 문맥·검색 대기·최신 요청 처리와 후보 선택 경합을 먼저 수정한다.
2. 라이브러리 미리보기·개별 복사·양쪽 초안 교체를 구현하고 취소·저장 실패·빈 원문을 검증한다.
3. 기존 태그 찾기 기능을 측면 버튼 패널로 이동하고 키보드·스크롤·초점·연속 삽입을 점검한다.
4. 기존 자동 테스트를 유지하고 실제 변경의 오류 경로를 검증하는 테스트를 추가한다. Android Chrome에서 IME·화면 검증을 수행하고 관리자의 삼성 브라우저 검증 항목을 갱신한다.
5. 구현 결과와 미검증 범위를 기록하고, 개인 데이터 포함 여부를 확인한 뒤 버전·변경 기록·배포를 정리한다. 이번 명세 작성만으로 앱 버전이나 배포 기능은 변경하지 않는다.

## 8. 검증 환경과 성능 판단

Android Chrome을 주 검증 대상으로 한다. 휴대폰 세로 화면, 키보드 열린 화면, 가로 회전, 태블릿과 좁은 분할 화면을 포함한다. 삼성 브라우저는 관리자 수동 검증을 요청하고 이번 개선을 실제 확인하기 전에는 통과로 표시하지 않는다. 기존 0.2.0 관리자 보고를 신규 U 기준의 통과 증거로 사용하지 않는다.

우선 확인할 실제 환경은 기존에 보고된 갤럭시 S25·탭 A11+다. 시행 당시 OS·브라우저·키보드 이름과 버전을 다시 기록한다. 삼성 키보드를 우선 확인하고 Gboard가 가용하면 교차 점검한다. 추가 설치나 도구가 필요하면 구체적 필요와 미검증 범위를 기록하고 그 시점에 요청한다.

기능 확인은 합성 데이터로 수행한다. 대규모 성능 확인은 관리자 단말의 개인 사전 또는 비슷한 규모의 합성 데이터로 하며, 검색 계산 p50/p95와 입력 대기 120ms를 포함한 후보 표시 시간을 구분한다. 기존 검색 계산 p95 150ms 이내 목표는 유지한다. PC 측정만으로 모바일 매 입력 검색의 부하를 판단하지 않는다. 정량 측정이 불가능하면 미측정으로 명시하며 대기 0ms로 전환하지 않는다.
